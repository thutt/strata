FEATURES THAT PROBABLY SHOULD BE IMPLEMENTED: A PROPOSAL
=========================================================

Written 2026-11-16, on the tree at commit 1e4c31c (branch port-to-c).  This
is a proposal.  The owner decides what is built.  Every ranking below was
made by the writer without asking, and each says why, so that the owner can
change it.


1. HOW THIS LIST WAS MADE
-------------------------

Sources, read together:

  - Appendix G of the reference manual, "Features of the original that
    Strata does not have" (manual/src/appnot.src and appnot1.src, taken
    from git: git show d7a1981:modernization/manual/src/appnot.src; d7a1981 is a
    commit of the old repository and is not in this one).  The
    appendix was removed from the manual; this document is where its
    information is kept.
  - docs/NOT-IMPLEMENTED.txt (written 2026-11-13, partly out of date now),
    docs/KEYSTROKES.txt (the keys marked "no"), docs/MARKERS.txt,
    docs/GLOBAL-MENU.txt, docs/PRINT-LATEX.txt and docs/TOOLS-MENU.txt.
  - The program as it is today: the menu tables and panels of src/ui.c,
    src/str.c, src/globalmenu.c, src/printmenu.c, src/filemenu.c and
    src/latex.c, and a search for "not available", "not implemented",
    "not decoded" and the dimmed entries.
  - The open items of docs/WORKLIST.txt.  An entry that is already an
    item there is named by the title of the item and is not repeated.

Size of work, an estimate made from the code that was read:

  S  a few functions in one or two files
  M  several files, or a new panel with its tests and documents
  L  a change of the data model, or a new module

Recommendation:

  IMPLEMENT  worth building soon, with the reason
  LATER      worth building, not now: what is needed first is said
  DROP       does not make sense today: why
  OWNER      only the owner can decide

3. THE RECOMMENDED ORDER OF THE IMPLEMENT ENTRIES
-------------------------------------------------

The order is by what a person who writes a long structured document of 700
or more pages will miss first, then by cost.

  1.  C1  Search and Replace options and the interactive Replace.  The
      editor is used for this all day; today Replace changes every
      occurrence at once with no way to say no.  M, Editor only, and no
      other entry waits for it.
  2.  B6  Page Break Level and the line and block spacing.  The user sets
      them on the Format panels and nothing happens: a setting that is
      shown and ignored costs trust.  S each, in the Printer.
  3.  D3a The table of contents of the print.  BUILT: the Print panels
      have Table of Contents? and Contents Levels.  A long document needs
      it first of the three lists.  The headline tags are the same on the
      screen and in the print.
  4.  B5  Headers and footers, with the Page Number and Section markers
      and the first, odd and even page layouts.  M to L.  DONE (alien-23):
      printed with fancyhdr, typed in the Page panels.
  5.  D1  Include.  BUILT: several authors each write a part in a file of
      their own and a master document includes the parts (collaborative
      editing, not a way to cut a long document).  M.
  6.  D3b The index from the Index markers, and D3c the lists of figures
      and tables from the Figure and Table markers.  M and S to M.
  7.  B2  Repaginate and Go To a page, with the page count on the screen
      (C4, C7 page keys).  L: the Editor must learn where the pages end.
  8.  A1  Maintain Dictionaries (the entry is on the Document Manager menu
      and says "not implemented"; the owner said it stays because it will
      be built; item "Document Manager: Maintain Dictionaries").  M.
  9.  A5  Initial Macro Set and Initial Library: the two Setup fields that
      are shown and cannot be used.  S.
  10. C8  The Case command (Upper, Lower, Capitalize) behind Ctrl-F6, and
      the small keys that are one function each (C7).  S.

Why 1 before 3 to 6: search is used in every session by every user, and a
list in a print is used once a release.  Why 2 before 3: the cost is one
macro in the preamble for each, and it removes the fields that do nothing.
Why 7 is late: it is the only large one, and a preview already shows the
pages.


4. THE ENTRIES, BY AREA
-----------------------

Each entry has: what the user would do; what exists today; how the work is
done without it; the size; what it depends on; the files it would touch;
the recommendation with the reason.


4.1 THE DOCUMENT MANAGER
------------------------

A1  Maintain Dictionaries  (the original: Maintain Spelling Dictionary)
  User would:  add words to the personal word list, remove them, see the
               list, for each language of the spell check.
  Today:       the entry shows the box "Not implemented".  Define on the
               check screen of Tools, Spell adds a word at once; many
               words are added by editing the file "dictionary" in the
               settings directory by hand.
  Without it:  edit that file with any text editor.
  Size:        M (a list panel in str.c, the file read and written, tests,
               documents).
  Depends on:  nothing; the personal list exists.  It also touches the
               Setup language field.
  Files:       src/str.c, the spell module, tests, manual (Document
               Manager chapter).
  IMPLEMENT:   the owner has said that the entry stays on the menu because
               it will be built; it is the only notice-only entry left.
               Worklist: "Document Manager: Maintain Dictionaries".

A2  Batch Print Utility and command files
  User would:  save the settings of a print in a file and run it later, or
               run a series of documents.
  Today:       the entry was removed from the Document Manager by the
               owner.  "stred --print" prints from a shell.
  Without it:  a shell script that calls "stred --print" for each document
               is a batch print, and it is a better tool.
  Size:        M.
  DROP:        replaced by the command line, which a shell, cron or make
               can drive.

A3  Import from 1-2-3 and Symphony, DCA files, ThinkTank outlines, image
    conversion, Document Downgrade
  Today:       none of these exists.  File Import and Export read and write
               text (UTF-8 and Latin-1 are choices).
  Without it:  save the data as text in the other program; make pictures
               as PNG or JPEG.
  Size:        L each.
  DROP:        they exist to work with programs and file formats of the
               1980s.

A4  Local Format Reset
  User would:  take every local format out of a document at one stroke,
               so that the global formats rule again.
  Today:       nothing; the user resets each block.
  Size:        S (walk the items and clear the format records).
  LATER:       cheap, but it destroys work and needs a confirmation panel
               and Undo to be safe.  Do it after the format settings are
               all used (B6).

A5  Initial Macro Set and Initial Library
  User would:  name a macro set and a library that the Editor loads when
               it starts.
  Today:       both fields are shown in Setup, marked (n/a), and cannot be
               set.
  Without it:  Tools, Macros, Retrieve and Tools, Library, Retrieve at the
               start of each session.
  Size:        S (two settings keys, the load at start in macro.c).
  Depends on:  the Setup panel (item "Document Manager: a better Setup").
  Files:       src/str.c, src/config.c, src/macro.c, tests, manual.
  IMPLEMENT:   a user who has macros wants them from the first key.  It
               also removes two dimmed fields.

A6  Maintain Download Fonts
  DROP:        replaced by TeX Font Association, and the system and the
               print queues manage printers and fonts now.

A7  Setup of drivers, memory and sound
  Today:       the fields are gone.  Done; not a candidate.


4.2 THE EDITOR MENUS
--------------------

B1  Edit, Window  (two windows)
  User would:  see two places of one document, or two documents, at once,
               and move text between them.
  Today:       the entry is dimmed.  A second Editor in a second terminal
               and the library (Ctrl-F3, Ctrl-F4) do the work.
  Size:        L: the Editor has one document, one cursor and one text
               area; a second view needs both split.
  LATER:       real value for a 700-page document (the text here, the
               table there), but it changes the core of the Editor.  Do
               it after Repaginate (B2), with Ctrl-W (switch windows).

B2  Print, Repaginate and Clear-pages
  User would:  see where each page ends, in the text, and clear the marks.
  Today:       both entries are dimmed; page breaks are known only to TeX
               when a print or a preview is made.
  Without it:  Preview shows the pages; a Final print says the number of
               pages.
  Size:        L: the Printer must tell the Editor which item starts each
               page (a map written by the run, for example from a label
               at each block), and the Editor must keep it and draw it.
  Depends on:  headers and footers (B5) change the page breaks, so build
               B5 first; "Go To a page" (C4) and the page keys (C7) use
               the same map.
  Files:       src/latex.c, src/strprint.c, src/view.c, src/ui.c.
  IMPLEMENT:   after B5.  It is the one large entry, and a long document
               needs the page count and Go To a page.

B3  File, Retrieve Named Block Settings Only
  Today:       the choice is in the list in parentheses and says "Named

  Size:        S to M (read the named format records of another file).
  LATER:       low value: named block formats are rare, and the other
               Retrieve choices cover the use.  Do it with the Global,
               Named panels if anyone asks.

B4  Global, Options: the fixed fields
  Today:       Block Indicators, Display Even Justification, Display

  B4c Block Indicators

  B4d Display Even Justification
      DROP: the screen is a grid of cells; evenly spread text cannot be
      shown on it.
  B4e Line Weight (Borders, Other)
      Size S once borders are drawn (C3).  LATER, with C3.

B5  Global, Page: headers, footers and the page layouts
  User would:  type a running head and a foot for the document, with the
               Page Number and the Section markers in them; choose
               another layout for the first, the even and the odd pages,

  Today:       the fields Header and Footer show "..." and cannot be

  Without it:  put the text of a running head in the first block of each

  Size:        M to L: an editor for the header and footer text (the

  IMPLEMENT:   the Page Number and Section markers exist only to be used

B6  Global, Format: the settings that are stored only
  Today:       the panels have every field; Spacing, Page Break Level,

  B6a Page Break Level (start a page at each section of a level and

  B6c Winding Columns and the Winding Column Layout panel (number of

  B6d Page Number Level, First Block Type, Print, the Ruler type

  B6e Fonts of the levels (the Font fields of the level panels).  Size M.

4.3 THE COMMANDS
----------------

C1  Search and Replace: the options
  User would:  match case or not, match a whole word, search by attribute,
               search for a tab, an end of line, a nonbreaking space or a
               marker; and on Replace choose the case of the replacement
               and say, at each hit: Replace, Once, Search, All or Quit.
  Today:       Search has Direction (Forward or Backward) and the choice
               Text or Print Error.  It ignores the case of letters and
               finds the string inside a word.  Replace asks two
               questions and changes every occurrence at once with the
               case as typed, then says how many.
  Without it:  make the string longer for a whole word; find each hit
               with F9 and change it by hand.
  Size:        M (two panels, a matcher with options, an interactive loop
               with Undo, tests, documents).
  Depends on:  Undo (done: one Replace All is one operation).
  Files:       src/ui.c, src/editor.c, tests, manual (Edit chapter, Search
               and Replace).
  DONE:        built (worklist: "Search and Replace: the options and the
               interactive Replace").  It was the most used command of the
               Editor with the fewest options, and "replace all or nothing"
               was dangerous in a long document.

C2  Compose (Alt-F1)
  User would:  type an accented or special character by a key sequence.
  Today:       Alt-F1 says "Alt-F1: not available"; the key strip shows
               the label Compose.  The keyboard layout and the system
               compose key do the work; characters outside code page 437
               become "?".
  Size:        S for a table of the characters of code page 437; M with
               UTF-8.
  Depends on:  the item "UTF-8 instead of the code page (explore)".
  OWNER:       either build it, or take the label off the key strip.  The
               compose key of the system works in the terminal and in X11
               for the characters that code page 437 has.

C3  The table editor and the borders  (F8 and Alt-F8)

               printed as table lines; they are not drawn on the screen

  Size:        M to L (a panel for column widths, border records, drawing

  Depends on:  B4e, the line weights.
  LATER:       technical documents have tables, but the F6 editor and the
               Ruler cover layout today.  OWNER: build it, or take the
               label Border off the key strip.

C4  Go To a page

4.4 MARKERS AND PICTURES
------------------------

D1  Include
  User would:  put another document into the print at the place of the
               marker, so that several authors, each editing a part in a
               file of their own at the same time, make one work that one
               print of the master shows whole.  (The owner: it is for
               collaborative editing, not for long documents; Strata
               handles 4000 pages in one document, but only one person
               can edit a document at a time.)
  Today:       BUILT (src/include.c; PRINT-LATEX.txt section 25).  The
               Printer joins the parts into the stream before the writer
               runs, in Final, Draft, Preview and part prints.
  Without it:  File, Retrieve with "Retrieve and Insert after the Current
               Section" puts a document into the text for good.
  Size:        M (the Printer reads the file, joins its items and its
               settings into the stream before the writer runs, as the
               conditional text does with its filtered copy; a loop guard
               for a file that includes itself; the positions of the
               diagnostics; the messages "Invalid Include request"; a
               test with a document of parts).
  Depends on:  the conditional text code (done) for the stream filter.
  Files:       src/latex.c, src/strprint.c, src/cond.c or a new module,
               tests, manual (Include marker page).
  BUILT:       the rules are in PRINT-LATEX.txt section 25: parts read
               at print time, found beside the including document then in
               the working directory, eight levels, a loop guard, the
               master's Global Format, numbering and contents through the
               parts, "Invalid Include request" with a notice at the
               place, tests tests/incltest.c, tests/include.py and a block
               of tests/smoke.py.

D2  Merge and Print Merge
  User would:  print one document once for each set of values of a merge
               document (a form letter); put a value in the text with a
               Merge marker.
  Today:       the Merge marker is stored and printed as its label; the
               Print panel has no merge document name.  Conditional text
               has the variables (the panel Variables, --var).
  Without it:  keep the letter and change the names with Replace, or call
               the Printer once for each set with --var.
  Size:        M to L (a merge document reader, a loop over the records,
               one PDF with all the copies, the Merge marker as a value
               of a variable).
  Depends on:  the variables (done); decision of the owner about what a
               merge document is (a document, or a CSV file).
  OWNER:       the owner read the feature as mail merge and large print
               jobs; the variables and "--var" already do half of it.
               LATER if the owner says yes.

D3  Index, Figure and Table markers, and the lists they make
  User would:  get a table of contents, a list of figures, a list of
               tables and an index in the print, each with its own layout.
  Today:       the three markers are stored and edited and printed as
               their labels; no list is made; the layout panels of the
               contents and the index are stored only.
  Without it:  write the list by hand; Cross-reference markers keep the
               section numbers true.
  D3a The table of contents.  Size S to M (LaTeX makes it from the
      headlines, which already have the tag of the screen; the layout
      panel of the contents; the Print field that asks for it).
      BUILT (the Print fields Table of Contents? and Contents Levels; the
      layout panel of the contents is not used; no marker: the original
      asks for it in the Print check list, and so does Strata).
  D3b The index.  Size M (the Index markers become entries; two runs of
      LaTeX and an index program, makeindex, which the TeX distribution
      has; the prerequisites list it; the index layout).  IMPLEMENT: the
      markers are already in the documents.  BUILT (alien-24): the Print field
      Index?, the index made in C and the page runs joined in LaTeX; makeindex
      is not used; the index layout panel is not used.
  D3c The lists of figures and tables.  Size S to M (the Figure and Table
      markers with their captions, and a list for each).  IMPLEMENT with
      D3a.  BUILT (alien-24): the Print fields List of Figures? and List of
      Tables?.
  Depends on:  B5 for the layout of the pages of the lists.
  Files:       src/latex.c, src/printmenu.c (the fields), src/globalmenu.c
               (layout panels), tests, manual.

D4  The Section marker and the Page Number marker in headers and footers
  See B5.  The Page Number marker already prints the page number in the
  body.  The Section marker prints as its label.

D5  The markers that were left out: Worksheet, Markup, Escape Codes,
    Symbol, Screen
  DROP:        decided.  A document that holds one keeps it unchanged.

D6  Graphics file formats of the original (PIC, metafiles, scanner files,
    printer description files)
  DROP:        they exist for programs and printers of the time.  The
               Picture marker takes PNG, JPEG, PDF and EPS.
  A modern addition is not in Appendix G: SVG pictures.  LATER (S to M:
  convert with a tool of the system into PDF when the file is read; add
  the tool to the prerequisites).

D7  Equations in the old language
  DROP:        decided; they are a defect of a document and the Printer
               reports them.

6. WHAT CAN BE BUILT AT THE SAME TIME
-------------------------------------

Two entries can be built at the same time on different machines when they
touch different files.  By the files that each touches, from the lists
above:

  Editor only (src/ui.c, src/editor.c):
      C1 Search and Replace; C8 Case.
  Printer only (src/latex.c, src/strprint.c):
      B6a Page Break Level; B6b Spacing; D1 Include; D3a, D3b, D3c the
      lists and the index.  These five share latex.c, so build them one
      after the other, or give each its own function and expect small
      merge conflicts.
  Document Manager only (src/str.c, src/config.c, src/macro.c):
      A1 Maintain Dictionaries; A5 Initial Macro Set and Library.  Both
      touch the menu and Setup code of str.c: one after the other.
  Printer and Editor together (not disjoint from the others):
      B5 headers and footers (globalmenu.c, latex.c, the text editor in
      ui.c), and B2 with C4 and C7 (latex.c, view.c, ui.c).

So the following sets are disjoint from each other and can run together:

  Set 1: C1 (Search and Replace) and C8 (Case)            Editor
  Set 2: B6a and B6b, then D3a, D3b, D3c, then D1         Printer
  Set 3: A1 and A5                                        Document Manager

B5 should start after Set 2 has made its changes to latex.c, and B2 after
B5.  The manual sources of the three sets are different chapters (Edit,
Print and markers, Document Manager), so the merges of the documents are
small.  A change of any of them also changes pictures: the picture check
(item "The picture check does not see the key strip") should be done first.
