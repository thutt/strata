1. THE FINDINGS IN ELEVEN LINES
----------------------------
  1. A default xterm does NOT send Esc for Alt.  It sends the character
     with the eighth bit set (written as UTF-8): Alt-o arrives as the
     letter i with a diaeresis.  Every Alt-letter command of the Editor
     (Alt-O overtype, Alt-I italics, Alt-0 to Alt-9 outline levels,
     Alt-Backspace, Alt-[ and Alt-]) types a character instead.  One
     resource cures it: XTerm*metaSendsEscape: true (probed, section 4.1).
     The manual says xterm "has a resource"; it does not say that the
     default is the bad one.
  2. xfce4-terminal keeps F1 (its help), F10 (its menu), F11 (full
     screen), Shift-F10, Ctrl-Minus (zoom), Ctrl-Insert, Shift-Insert,
     Shift-Home, Shift-End, Shift-Up, Shift-Down, Shift-PgUp, Shift-PgDn
     and the Menu key.  F1 is the Help key of the Editor, and Shift-Up,
     Shift-Down, Shift-Home and Shift-End move to the headline of the
     section and to the start and end of the document.
  3. xterm and tmux keep only Shift-Insert, Shift-PgUp and Shift-PgDn
     (xterm: paste and scrollback) and, for tmux, its prefix Ctrl-B.
  4. GNOME (probed from the installed schemas of GNOME 48) takes Alt-F1,
     Alt-F2, Alt-F4, Alt-F5, Alt-F6, Alt-F7, Alt-F8 and Alt-F10, and
     Alt-Tab, Alt-Space and Ctrl-Alt-letters and arrows.  Xfce takes
     Alt-F4, F6, F7, F8, F9, F10, F11 and ALL of Ctrl-F1 to Ctrl-F12
     (workspaces).  KDE takes Alt-F2, Alt-F3, Alt-F4 and Ctrl-F1 to
     Ctrl-F4 (and by its manual Ctrl-F7, F9, F10 and F12).  So there is no
     Alt-function key and no Ctrl-function key that is safe everywhere.
  5. The Editor has an alternative for the Alt-F commands: Ctrl-F (a
     menu), Ctrl-F12, Alt-O.  At the time of the study four groups of
     commands had NO key and NO menu entry that worked when their key was
     taken: Border, Math, Case, the Library commands, Search Again and
     Redo.  That gap is closed (task W29.2): every command that has a
     function key is in the F12 menu now (docs/KEY-MAP.txt, part 4).
  6. Compose (Alt-F1) and Alt-F10 and Alt-F11 do nothing yet, so losing
     them costs nothing.
  7. The F12 menu is safe in every environment tried except the quake
     style terminals (Guake, Yakuake: documented, not probed).
  8. Ctrl-Alt-F1 to Ctrl-Alt-F12 switch virtual consoles (Linux console,
     GNOME on Wayland) and are not used by the Editor.
  9. Over ssh a line that begins with a tilde followed by a full stop
     ends the connection: typing "~." at the start of a line in a document
     over ssh disconnects (documented in ssh(1)).
 10. The Editor does not read the key forms Esc O m P to S (a modifier
     digit after Esc O), which the terminfo entry of konsole gives for
     Shift-, Ctrl- and Alt-F1 to F4: the commands of those keys fail and
     the letter after the digit is typed (section 4.2).
 11. The smallest fix for release 1 is one popup that lists EVERY command
     that has an Alt or Ctrl function key, reached by Ctrl-F and by the
     F12 menu (section 6), and a small change of the terminal driver to read
     Esc O m P to S.  No key has to be moved.

4. WHAT EACH ENVIRONMENT DOES WITH THEM
---------------------------------------
Rows list only keys that the Editor uses.  "arrives" means the program
gets the key unchanged.  "taken" means the environment keeps it and the
Editor never sees it.

4.1 Terminals, probed (Xvfb, no window manager, xdotool keys, key logger)
  xterm 407 with its default resources: every key of section 3 arrives as
  the xterm sequences, EXCEPT:
    Shift-Insert, Shift-PgUp, Shift-PgDn      taken (paste, scrollback)
    Alt with a character                      ARRIVES AS A DIFFERENT KEY:
        the character with the eighth bit set, in UTF-8: Alt-o is the two
        bytes c3 af, Alt-i is c3 a9, Alt-1 is c2 b1, Alt-Backspace is c3 bf,
        Alt-+ is c2 ab, Alt-[ is c3 9b.  The Editor types these characters.
    Ctrl-Alt with a function key              nothing arrives (not used)
  xterm with  -xrm 'XTerm*metaSendsEscape: true':  Alt-o is Esc o (1b 6f),
    Alt-1 is Esc 1, Alt-Backspace is Esc DEL, Alt-[ is Esc [ ...: the form
    that the Editor reads (docs/KEYSTROKES.txt).  Everything else as above.
    The manual's appendix D (appterm-esc) tells the reader that the terminal
    must send Esc for Alt, but it does not say that xterm does not, and a
    reader who starts xterm and tries Alt-O sees a character.
  xfce4-terminal (GTK, VTE), its default shortcuts: taken are F1 (help),
    F10 (menu), F11 (full screen), Shift-F10 (context menu), Ctrl-Minus
    (zoom out), Ctrl-Insert, Shift-Insert, Shift-Home, Shift-End, Shift-Up,
    Shift-Down, Shift-PgUp, Shift-PgDn and the Menu key.  Alt with a
    character arrives as Esc and the character (the form the Editor reads).
    Ctrl-Alt with a function key: nothing arrives.  The installed program
    has the switches "Disable all menu access keys (such as Alt + f)" and
    "Disable menu shortcut key (F10 by default)" in its preferences
    (found in the program; the label "Advanced" is not verified); F1 and
    F11 are changed in its Shortcuts page.
  tmux 3.5a inside xterm: taken are Shift-Insert, Shift-PgUp, Shift-PgDn
    (the outer xterm) and Ctrl-B (the tmux prefix; Ctrl-B is Bold in the
    Editor: press it twice, or set the prefix in ~/.tmux.conf).  Home and
    End arrive as Esc [ 1 ~ and Esc [ 4 ~ (the older form; the Editor reads
    them as Home and End); the Menu key arrives as the sequence of Shift-F6.
    Alt with a character: as the outer terminal.  Modified function keys
    arrive as the xterm sequences.
  One key list, 154 keys, each with the bytes: tools/keyprobe.py term.

4.2 What the Editor reads from the terminal types of terminfo
  Method (probed, Editor): for 15 terminal types the sequences that the
  terminfo entry gives for the function keys were typed into the terminal
  version of the Editor in a pty, and the screen was compared with the
  screen after the key that the sequence stands for (tools/keyprobe.py
  terminfo; the Editor does not read TERM).  The terminfo entry says what a
  terminal type should send; a real terminal may send something else (see
  xfce4-terminal below), so the run finds the sequences the Editor does not
  read, not what a terminal does.
    Plain F1 to F12   read correctly for linux, xterm, xterm-256color,
                      screen, tmux-256color, rxvt-unicode-256color, st,
                      kitty, alacritty, foot, konsole, gnome, xfce, putty.
                      For vt100 F5 to F9 (Esc O t, u, v, l, w) are NOT read
                      (a vt100 has no F11 and F12 either).
    Ctrl-F1 to F12 and Alt-F1 to F12 (kf25 to kf36 and kf49 to kf60 of the
                      xterm family) are read correctly when the sequence is
                      Esc [ 1 ; m P to S or Esc [ n ; m ~ : xterm,
                      xterm-256color, tmux-256color, st, kitty, alacritty and
                      foot.  (Two pairs look wrong in the comparison, Ctrl-F7
                      with Ctrl-F8 and Ctrl-F12 with Alt-F12; they are the
                      same on the screen because the commands give the same
                      message, so they are right.)
    NOT READ: Esc O m P to S (m is the modifier digit).  The terminfo entry
                      of konsole gives Esc O 5 P for Ctrl-F1, Esc O 3 P for
                      Alt-F1 and Esc O 2 P for Shift-F1, in the same form
                      for F2, F3 and F4.  The Editor reads Esc O 5 as a key
                      and then TYPES the letter P into the document (tried:
                      the text gets the letter).  So in a terminal that
                      sends these (Konsole by its terminfo entry; not
                      probed live) the commands of Ctrl-F1 to Ctrl-F4 (Learn,
                      Math, Lib Copy, Lib Cut) and of Alt-F1 to Alt-F4
                      (Compose, Append, Join, Delete) do not work, and
                      Shift-F1 to Shift-F4 type P, Q, R, S.  The terminfo
                      entries gnome and xfce give Esc O 1 ; 5 P, which is
                      read in the same way (the letters ;5P are typed), but
                      xfce4-terminal was probed live and sends Esc [ 1 ; 5 P
                      (section 4.1), so those two entries do not describe it.
    No sequence at all: the entries of linux, screen, rxvt-unicode-256color,
                      vt100 and putty have no Ctrl-F or Alt-F keys.  In them
                      Ctrl-F1 to Ctrl-F12 and Alt-F1 to Alt-F12 cannot be
                      typed (the console sends Shift-F1 to Shift-F10 as the
                      codes of F11 to F20).  Every command on those keys
                      needs the popup (section 6).
    Cursor keys, Home, End, Ins, Del, PgUp, PgDn: the comparison cannot tell
                      them apart on the screen of a one line document, so
                      they are not reported; the probed sequences of xterm,
                      xfce4-terminal and tmux (4.1) are the xterm forms and
                      the older Esc [ 1 ~ and Esc [ 4 ~, which the Editor
                      reads (src/term.c: the codes 1, 7 and 4, 8).

4.5 ssh, forwarding and the Linux console
  ssh (documented, ssh(1) on this machine): "The escape character must
    always follow a newline to be interpreted as special."  The escape
    character is the tilde: ~. disconnects, ~^Z suspends ssh, ~? shows
    help, ~C opens a command line.  In the terminal version of the Editor
    over ssh, typing a tilde and a full stop at the start of a line (right
    after Enter) ends the connection.  Cures: ~~ sends one tilde; -e none
    or EscapeChar none turns the feature off.
  Linux console (the kernel keymap, documented in kbd(4); not probed: a pty
    is not a console):  Alt-F1 to Alt-F12 switch to virtual console 1 to 12
    in the default keymap; Ctrl-Alt-F1 to F12 as well; Shift-PgUp and
    Shift-PgDn scroll the history; the function key sequences of terminfo
    linux are Esc [ [ A to Esc [ [ E for F1 to F5 and Esc [ 17 ~ for F6 and
    so on; Shift-F1 to Shift-F10 send the codes of F11 to F20 (the manual's
    appendix D says this too).  The manual's appendix D has a row for each.

6. RECOMMENDATION FOR RELEASE 1
-------------------------------
Smallest set of changes that makes every command reachable in the common
environments (a terminal on GNOME, Xfce or KDE; the Linux console; xterm,
xfce4-terminal and tmux), keeping every key as it is:
  1. ONE POPUP FOR ALL COMMANDS.  Extend the Ctrl-F popup ("Alt commands")
     to a list of every command that has an Alt or Ctrl function key, with
     the key shown: add Border, Math, Case, Lib Copy, Lib Cut, Lib Paste,
     Search Again, Undo, Redo, Learn and Help to the ten entries it has,
     and put the same entries in the F12 menu (Tools gets Math, Case and
     the three Library commands; Edit gets Border).  Every command is then
     reached by Ctrl-F (the byte 6: no terminal, window manager or console
     keeps it, section 4) or by F12.  Size S: the handlers exist.
  2. HELP WITHOUT F1.  Done: Help is in the F12 bar (W29.2).  F1 stays.
  3. TELL THE USER ABOUT XTERM.  In the manual's appendix D and in the
     getting started text: for xterm, start it with
         xterm -xrm 'XTerm*metaSendsEscape: true'
     or put the line in ~/.Xresources.  This is the only Alt cure that
     the study found; it is worth a start check (the terminal start check
     W15 cannot see it: the Editor cannot tell the character a user typed
     from the same character sent by Alt).
  4. TELL THE USER ABOUT THE TERMINALS' OWN KEYS.  Add rows for
     xfce4-terminal (F1, F10, F11, Shift-cursor keys, Ctrl-Minus), xterm and
     tmux (Shift-Insert, Shift-PgUp, Shift-PgDn, Ctrl-B), konsole
     (Shift-Left and Shift-Right) to the table "Keys that a terminal keeps
     for itself" (appterm-reach), each with the way to give the key back or
     the alternative (section 5).
  5. A TABLE FOR WINDOW MANAGERS in the terminal and X11 appendices: GNOME,
     Xfce and KDE from section 4.4, with the line that every command has a
     route by Ctrl-F or F12.
  6. THE ssh TILDE: one line in the terminal appendix (links and slow
     lines): "~." at the start of a line over ssh disconnects; type ~~ or
     start ssh with -e none.
  7. READ THE SHIFTED SS3 FORMS.  The terminal driver (src/term.c) should
     read Esc O m P to S and Esc O 1 ; m P to S as F1 to F4 with the
     modifier m (m is 1 plus 1 for Shift, 2 for Alt and 4 for Ctrl: 2 is
