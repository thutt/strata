OBSERVATIONS FROM RUNNING THE ORIGINAL UNDER DOSBOX-X
=====================================================

The original MS.EXE runs unmodified in DOSBox-X (installed from driver_1, the
other disks' programs and the samples copied onto a scratch DOS drive, never the
source tree). It needs its first-run Setup (it writes MS.VAL); after that the
Document Manager and the editor work. Screens were captured with xwd and
measured cell by cell (80 columns = 540 px, 6.75 px per cell). The driving
scripts (DOSBox-X config, xdotool key sender, screenshot converter) lived in a
scratch directory outside this tree and are not part of the project.

Settled questions
-----------------

  - Are the 11 tab-width "mismatches" in scr.doc a layout defect?: No -- the
    stored count is a stale cache. In the original the bullet sits in the
    column's first cell, the tab glyph in the second, and the text starts at
    offset 5 (the global tab stop FTT5), with the hanging indent also at 5.
    The file's stored fill (2) would put it at 4. The original recomputes tab
    layout from the stops; so does stred, so its display matches. The stored
    values are only reproduced for blocks where they were current.
  - What do CL / CR mean?: Left and right gap cells of a column. A column
    occupies CL + CW + CR cells, the text starts CL cells in, and one separator
    cell follows the slot. Verified on CW15 CR2 (slot 17) and CW25 CL1 CR1 (slot
    27).
  - Is there a default level indent?: No. Without an FI<n> header record
    sections are not indented (cns10pp.doc); with FI3 level *n* is indented
    (n-1)*3 (level 3 -> 6 cells in scr.doc). My earlier default of 3 was wrong.
  - What shows the section number ("1", "1.1", "1.1.6")?: The original draws the
    section tag before the headline text unless the header has FLA0 (present in
    music.doc, sample3.doc, cns10pp.doc; absent in scr.doc, which shows
    numbers). FLA0 is therefore very likely "no section tags". stred now draws
    them: default 1.1.6  full-path numbering, custom F<level>G formats (Part
    \I\. , \A\. ) with decimal, roman and letter counters, none when FLA0.
  - How is a Picture marker displayed?: Short form, [PIC MUSBAR.GMF], not
    [Picture ...]. stred now matches.
  - Are end-of-line and tab characters visible?: Yes by default: < (CP437 0x11)
    at each end of line and > (0x10) for the first cell of a tab (option
    "Display Tab & End-of-Line Characters?"). stred now shows them by default
    and has the option.
  - Is there a border on columns?: Yes: CB draws box lines in the gap cells
    (coloured), e.g. around the whole table and around the picture column. Not
    drawn by stred yet (worklist).

Screen layout (now matched by stred)
------------------------------------

  - Row 0: status line (SCR.DOC  Attr: Bold  Pos: 3  Sect: 1  STRUCTURED EDIT,
    reverse video).
  - Row 1: the ruler directly under it (dots, tab glyphs). The expanded status
    line is off by default.
  - Last two rows: a two-row key panel -- F1: Help  F3: Copy  F5: Paste  F7:
    Move  F9: Search over F2: Split  F4: Cut  F6: Format  F8: Table  F10: Menu.
  - Headlines are bold and centred when FxHJ2; blocks are separated by a single
    rule, sections by a double rule.

Panels (now matched by str where marked)
----------------------------------------

  - Document Manager: titled double-line box "Document Manager Release 2.1",
    entries left-aligned, highlighted bar, bottom border "Press Ins to Select
    Action".
  - Setup: Text Display Driver (the default was *Alternate Color Graphics*),
    Graphics Display Driver, Primary/Secondary Print Driver with Port, Virtual
    Memory Setup, Sound, Initial Macro Set, Initial Library, Dictionary
    Language, Decimal Separator, Initial Working Directory -- as in the help.
  - Edit Document: Working Directory first (C:\MS\), then Document Name; the
    bottom border reads "Press Ins to Edit Document" and the right end of it
    shows the settings name DEFAULT. (str now uses this field order.)
  - Search (F9): Search String, Direction (Forward), then "Search Options":
    Match Lowercase With (Any Case), Attributes (Any), Match Complete Word?
    (No); "Press Ins to Begin". (stred has only the string -- worklist.)

Still open

numbers other than those observed; counter evaluation. These need more driving
of the original (open a document, change an attribute, observe), which is
straightforward now that it runs.
